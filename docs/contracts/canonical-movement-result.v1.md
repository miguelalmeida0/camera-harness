# Canonical Movement Result v1

## Purpose

Provide a stable, conservative identity for deterministic recipe matching while preserving the natural-language movement sentence as the user-facing result.

## Schema

```json
{
  "schema_version": "canonical-movement-result.v1",
  "movement_result_id": "movement_...",
  "movement": "You raised your hand and made a peace sign.",
  "short_label": "Peace sign",
  "movement_key": "peace_sign",
  "gesture_tags": [
    "hand_gesture",
    "two_fingers_raised",
    "hand_raised"
  ],
  "confidence": 0.87,
  "reason": "Visible hand shape and movement were consistent across the frame sequence.",
  "evidence": [
    "hand position changed across frames",
    "two raised fingers were visible",
    "movement happened during capture window"
  ],
  "uncertainty": false,
  "requires_confirmation": true
}
```

## Field Rules

- `schema_version`: exactly `canonical-movement-result.v1`.
- `movement_result_id`: unique for one normalized result snapshot and stable across rerenders; generated by DarkQuest, not trusted from provider prose.
- `movement`: concise user-facing hero sentence.
- `short_label`: concise display label; never used alone to authorize an action.
- `movement_key`: conservative lowercase snake_case identifier matching `^[a-z][a-z0-9_]{1,63}$`.
- `gesture_tags`: deduplicated safe behavioral tags, each using lowercase snake_case; maximum 12.
- `confidence`: finite number from 0 through 1; it is a model estimate, not proof.
- `reason`: sanitized text, maximum 500 characters.
- `evidence`: sanitized text-only observations, maximum 5 items and 240 characters per item.
- `uncertainty`: true when the temporal change, gesture, or canonical identity is unclear.
- `requires_confirmation`: always true in v1.2.

## Canonicalization Rules

- `movement` remains the hero sentence; machine fields stay hidden from the main product.
- `movement_key` must represent visible behavior, not intent or identity.
- Use `movement_key: "uncertain"` and `gesture_tags: []` when a conservative key cannot be assigned.
- `gesture_tags` may describe visible behavior such as `hand_raised` or `lateral_motion`; they must not contain identity, sensitive attributes, appearance judgments, inferred health status, or biometric identity.
- Unknown fields are ignored during provider normalization and are not copied into automation context.
- Normalization forces `requires_confirmation: true` even if the provider returns false.

## Automation Eligibility

A result is eligible for matching only when all are true:

- the schema is valid;
- the user explicitly confirmed this exact `movement_result_id`;
- `uncertainty` is false;
- `movement_key` is not `uncertain`;
- confidence meets the recipe threshold.

Corrected text may become a local, user-approved recipe alias. Corrections never carry images and cannot silently replace the canonical key. A correction without an explicit alias mapping remains non-executable for that alias.

## Privacy Boundary

The contract contains text metadata only. It forbids raw frames, screenshots, audio, OCR, base64, identity, sensitive attributes, and biometric templates.
