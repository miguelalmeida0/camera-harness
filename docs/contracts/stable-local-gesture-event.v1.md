# Stable Local Gesture Event v1

## Schema

```json
{
  "schema_version": "stable-local-gesture-event.v1",
  "gesture_event_id": "gesture_session1_000001",
  "gesture_key": "thumbs_up",
  "source": "mediapipe_gesture",
  "confidence": 0.91,
  "first_seen_ms": 0,
  "stable_at_ms": 380,
  "held_for_ms": 380,
  "hand_count": 1,
  "requires_neutral_reset": true,
  "contains_raw_media": false
}
```

## Field Rules

- `schema_version`: exactly `stable-local-gesture-event.v1`.
- `gesture_event_id`: unique monotonic session ID generated by the stabilizer, stable across UI rerenders.
- `gesture_key`: one of the seven v1.2.1 canonical keys.
- `source`: exactly `mediapipe_gesture`.
- `confidence`: minimum category score observed at stable emission, from 0 through 1.
- `first_seen_ms`, `stable_at_ms`, and `held_for_ms`: monotonic-clock values; `held_for_ms = stable_at_ms - first_seen_ms` within sampling tolerance.
- `hand_count`: integer 1 or 2; no hand identity is stored.
- `requires_neutral_reset`: true in v1.2.1.
- `contains_raw_media`: always false.

## Stabilizer State Machine

`disarmed -> neutral_armed -> candidate -> emitted_waiting_neutral -> neutral_armed`

- `disarmed`: toggle off, camera stopped, tab hidden, worker unavailable, or lifecycle teardown.
- `neutral_armed`: no supported above-threshold gesture is active; a new candidate may begin.
- `candidate`: the same canonical top gesture remains at or above the recipe threshold.
- `emitted_waiting_neutral`: one event was emitted; repeated frames cannot emit again.

A candidate resets when its key changes, confidence drops below threshold beyond the allowed sampling gap, camera stops, tab hides, or the worker resets. Neutral means no supported above-threshold gesture for a bounded neutral interval. Rearming requires neutral reset and does not bypass recipe cooldown.

## Emission Rules

- Gesture remains above the configured threshold for the configured hold time.
- Emit exactly one event for one stabilized hold.
- Require neutral/no-gesture before rearming.
- Apply recipe cooldown independently after matching.
- Camera or result rerenders cannot reset or duplicate worker/stabilizer state.
- Hidden tab or stopped camera disables candidates and events immediately.
- Only symbolic fields above leave the worker/controller boundary; raw frames, landmarks, and image buffers are excluded.

Every stabilizer update returns `{ state, event, code }`. `event` is non-null only on stable emission. The stabilizer codes are exact:

- `instant_gesture_below_threshold`: a supported gesture is present below the configured confidence threshold.
- `instant_gesture_hold_not_met`: a candidate is above threshold but has not reached `hold_ms`.
- `instant_gesture_duplicate`: the current uninterrupted hold already emitted, or the same `gesture_event_id` was delivered again.
- `instant_gesture_neutral_reset_missing`: emission occurred and the required neutral interval has not completed.
- `instant_gesture_cooldown_active`: neutral reset completed but the relevant cooldown has not expired.

The worker result must include `hand_count`; the controller carries it into the stabilizer. Legacy `started_at_ms` and `hold_ms` event fields are not canonical substitutes for `first_seen_ms` and `held_for_ms`.

## Idempotency

Each recipe execution uses `gesture_event_id + recipe_id`. Duplicate event delivery returns the existing execution state or receipt and never calls the adapter twice.

## Runtime Observability Contract

The local gesture controller maintains one text-only diagnostics object. Research Lab may render these fields while remaining hidden by default:

```ts
type LocalGestureRuntimeDiagnosticsV1 = {
  recognition_loop_running: boolean;
  frames_processed: number;
  last_frame_timestamp: number | null;
  last_raw_label: string | null;
  last_raw_confidence: number | null;
  mapped_gesture_key: string | null;
  current_hold_ms: number;
  required_hold_ms: number;
  last_stable_event_id: string | null;
  last_match_outcome: string | null;
  last_execution_outcome: string | null;
  last_receipt_id: string | null;
  safe_error: string | null;
};
```

Field semantics:

- `recognition_loop_running` is true only while camera frames are actively scheduled for local inference.
- `frames_processed` increments only after inference completes, including a valid no-gesture result.
- `last_frame_timestamp` is the timestamp of that completed inference.
- `last_raw_label` and `last_raw_confidence` are the latest bounded MediaPipe result; `None` is valid.
- `mapped_gesture_key` is the canonical mapping or null.
- `current_hold_ms` is zero without an active candidate and otherwise derives from the monotonic candidate start.
- `required_hold_ms` comes from the active matching recipe set.
- `last_stable_event_id` changes only when a complete stable event emits.
- Match, execution, and receipt fields contain bounded symbolic IDs or outcome codes only.
- `safe_error` is redacted and never contains a token, URL credential, stack, or media value.

The diagnostics object must not contain images, base64, frame bytes, object URLs, landmark history, audio, provider tokens, raw frames, or unrestricted model output.

## Diagnostic Classification

| Condition | Required text-only evidence |
| --- | --- |
| No inference frames | Loop false, or `frames_processed` unchanged |
| MediaPipe returns no gesture | Frames increase; raw label `None`; mapped key null |
| Confidence below threshold | Raw confidence below threshold; below-threshold outcome |
| Hold duration not met | Mapped key present; current hold below required hold |
| Recipe not matched | Stable event ID present; match outcome records no match |
| Action blocked | Match present; execution outcome records policy denial |
| Speech adapter failure | Execution failure code and safe error; no success receipt |
