# Gate 2A Minimal State-Backed HUD Polish

## Purpose

Gate 2A exists to make the local Focus Ritual app clearer, cleaner, more usable, and more confidence-inspiring without adding fake intelligence, hidden inference, or cinematic presentation.

Gate 2A is visual and operational polish only. It must stay backed by replayed state, stable events, HUD commands, evidence, confidence, latency, privacy, model-call status, export status, validation status, and accepted disclosure.

## Relationship To Gate 1C

Gate 1C is `PASS_WITH_DISCLOSURE`.

Accepted evidence:

- physical trace: `PASS`;
- physical trace origin: `PASS`;
- replay: `PASS`;
- privacy: `PASS`;
- model calls: `PASS`;
- memory: `PASS`;
- HUD honesty: `PASS`;
- waiver: accepted;
- raw media persistence: `0`;
- LLM/VLM calls: `0`.

Disclosed limitation:

- static validation remains failed and waived for this narrow scope.

Gate 2A may proceed only as minimal state-backed HUD/debug polish with visible disclosure. This does not approve cinematic HUD, portfolio demo claims, autonomous vision claims, production claims, model integration, VLM integration, narration, or agentic embellishment.

## Allowed

- layout cleanup;
- typography hierarchy;
- spacing;
- status bar clarity;
- checklist clarity;
- event timeline readability;
- sequence inspector readability;
- export and save-path clarity;
- validation command UX;
- bug report UX;
- troubleshooting UX;
- confidence, latency, privacy, and model status display.

## Forbidden

- cinematic effects;
- portfolio-ready visuals;
- fake progress;
- hidden manual confirmation;
- hidden uncertainty;
- hidden low confidence;
- autonomous vision claims;
- model or VLM claims;
- raw media persistence;
- new model calls;
- narration;
- agentic embellishment.

## State-Backed Visual Rule

Every visible progress, status, checklist item, timeline row, badge, banner, warning, and control state must map to one or more accepted symbolic inputs:

- quest state;
- stable event;
- HUD command;
- event evidence;
- confidence value;
- latency metric;
- privacy status;
- model-call status;
- export status;
- validation status;
- waiver/disclosure status.

If the backing state is missing, stale, uncertain, or waived, the UI must show that honestly. It must not fill gaps with optimistic copy, animation, decorative success states, or implied perception.

## Disclosure Rule

Gate 2A UI must disclose in dev/debug mode:

- package-local static validation is waived;
- minimal HUD polish is allowed with disclosure;
- manual confirmations are not autonomous vision;
- no LLM/VLM calls are used;
- no raw media is persisted.

Disclosure may be compact, but it must be visible and testable.

## Manual Confirmation Rule

Manual confirmation must remain obvious anywhere it can affect quest progress.

Allowed language: `manual local confirmation`, `operator confirmed`, `symbolic event`.

Forbidden language: `autonomous vision`, `AI vision proven`, `automatically understands your desk`.

## Privacy And Model Visibility Rule

The HUD must keep privacy and model-call status visible enough for an operator to verify:

- raw media persistence is `0`;
- LLM/VLM calls are `0`;
- model integration is not active;
- exported artifacts are symbolic traces, not camera media.

## Validation And Export Visibility Rule

The HUD must make trace export, save path, validation commands, and validation result state easy to find. Export success must not imply Gate 1C success unless validation and replay have actually passed.

## No-Cinematic Boundary

Gate 2A polish may make the app calmer and clearer. It may not make the app look like a cinematic demo, portfolio case study, autonomous AI product, or production-ready system.
